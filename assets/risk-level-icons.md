# 风险等级标识规范

> 安全审计报告中使用的风险等级颜色/图标标识标准

---

## 四级风险定义

```
┌─────────────────────────────────────────────────────────────────┐
│                     风险等级标识规范                              │
├──────────┬──────────┬──────────────────────────────────────────┤
│ 等级     │ 图标      │ 含义                                     │
├──────────┼──────────┼──────────────────────────────────────────┤
│ CRITICAL │ 🔴 [C]   │ 可直接利用，需立即修复                      │
│ HIGH     │ 🟠 [H]   │ 风险较高，24小时内修复                      │
│ MEDIUM   │ 🟡 [M]   │ 需要关注，计划修复                         │
│ LOW      │ 🟢 [L]   │ 低风险，择机优化                           │
└──────────┴──────────┴──────────────────────────────────────────┘
```

---

## 🔴 CRITICAL — 严重

**图标:** 🔴 `[C]` `██████████` (纯色填充块)

**定义:** 漏洞可被攻击者直接利用，无需特殊条件，可能导致：
- 完整系统被入侵
- 大规模数据泄露（用户密码、个人信息）
- 远程代码执行（RCE）
- 服务器被完全控制

**响应时间:** 立即修复（0-4 小时内）

**典型漏洞:**
- SQL 注入（字符串拼接）
- 命令注入（os.system + 用户输入）
- 硬编码 AWS 密钥 / 私钥泄露
- 远程代码执行
- 反序列化漏洞（pickle.loads 未信任数据）
- .env 文件已提交到 Git 仓库

**修复要求:**
- 必须在合并/发布前修复
- 需要 Code Review 二次确认
- 修复后需回归测试

---

## 🟠 HIGH — 高危

**图标:** 🟠 `[H]` `▓▓▓▓▓▓▓▓░░` (四分之三填充)

**定义:** 漏洞有明确攻击路径，需要一定条件利用，可能导致：
- 部分敏感数据泄露
- 水平/垂直越权
- XSS 攻击（窃取 Cookie/Token）
- 不安全的反序列化
- 弱加密导致数据可被破解

**响应时间:** 24 小时内修复

**典型漏洞:**
- XSS（innerHTML 直接插入用户输入）
- IDOR（直接使用数据库 ID 无归属校验）
- JWT 硬编码密钥
- CORS 过度开放
- 不安全的 TLS 配置
- 存在已知 CVE 的依赖组件

**修复要求:**
- 在当前迭代内修复
- 纳入 Sprint 任务

---

## 🟡 MEDIUM — 中危

**图标:** 🟡 `[M]` `▓▓▓▓░░░░░░` (半填充)

**定义:** 漏洞存在但难以直接利用，或需要特定环境条件：
- 安全配置缺陷
- 信息泄露（错误堆栈、版本号）
- 会话管理不当
- 缺少安全头

**响应时间:** 1-2 周内修复

**典型漏洞:**
- DEBUG=True 在生产环境
- HTTP 安全头缺失
- Cookie 缺少 Secure/HttpOnly 标志
- 目录列表未禁用
- 错误信息泄露内部路径
- 使用 MD5/SHA1 做非密码哈希

**修复要求:**
- 纳入技术债务清单
- 定期审计确认

---

## 🟢 LOW — 低危

**图标:** 🟢 `[L]` `▓▓░░░░░░░░` (四分之一填充)

**定义:** 最佳实践建议，安全影响有限：
- 代码风格/架构层面的安全改进建议
- 缺少锁文件
- 依赖版本略旧但无已知 CVE
- 日志格式不够规范

**响应时间:** 择机优化，不阻塞发布

**典型漏洞:**
- 缺少 poetry.lock / go.sum
- 日志未结构化
- 缺少 API 版本号
- 依赖未使用最新稳定版（无 CVE）
- 缺少 .gitattributes

**修复要求:**
- 作为日常代码质量改进处理

## 使用规范

### 报告中的展示格式

```
🔴 CRITICAL | CWE-89 | SQL 注入 | src/api/user.py:42
  └─ 修复: 使用参数化查询

🟠 HIGH | CWE-79 | XSS | src/components/Comment.jsx:15
  └─ 修复: 使用 DOMPurify 清洗

🟡 MEDIUM | CWE-489 | 调试模式 | config/production.py:3
  └─ 修复: DEBUG = False

🟢 LOW | CWE-1104 | 缺少锁文件 | go.mod
  └─ 修复: 运行 go mod tidy
```
